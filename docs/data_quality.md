# 健身数据质量备忘（data_quality.md）

> 数据范围：2026-08-01 ~ 2026-09-30，共 61 个日历日
> 实际记录：【50】天，缺失【11】天（缺失率约 18%），另有 1 个半记录日（09-24）
> 本文档说明四类质量问题及处理规则，每条规则在清洗代码中均有对应实现。

## 一、缺失日清单及原因（共11天）

| 日期 | 分类 | 说明 |
|------|------|------|
| 08-08、08-09 | 外出未记录 | 出去玩，体重饮食均未记录 |
| 08-17、08-26、09-04、09-06、09-27 | 整日漏记 | 未训练，也未记录 |
| 09-13、09-17、09-22、09-26 | 练了但没记 | **训练日志有记录，但当日整行缺失** |

处理方式：缺失日不造数、不填0；仅体重列在计算移动平均时做插值（并注明）。

交叉校验结果：
- 训练日志有记录、但每日记录整行缺失：4 天（上表第三类）
- 每日记录标记训练日=1、但训练日志无记录：**0 天**（该方向两表完全一致）
- 每日表存在、但体重缺失：1 天（09-24，即下方"半记录日"）

## 二、特殊日处理规则

区分三类"需要小心使用"的日子，处理方式不同：

**1. 部分记录日 —— 不能代表全天摄入**
- 操作定义：总热量缺失，或总热量 < 800 kcal
  （阈值依据：本人记录完整的日子热量均在 840 以上，只记一餐的两天为 640/720，
  640/720 < 800 < 840，两类仍干净分开）
- 命中：08-07、08-13、08-16、08-21、09-19、09-24、09-28，共 7 天
- 处理：保留行，但不参与热量/蛋白质的均值计算
- 理由：只记一餐时数值无法代表全天，混入均值会严重低估摄入
- 补录注：09-08 为事后补录日，数值按实测保留并标注补录来源；
  SQL 重建审计后部分记录日实为 8 天（上列 7 天 + 09-08）

**2. 特殊事件日 —— 记录完整、数值真实，但行为特殊**
- 操作定义：部分记录=False 且热量显著高于日常水平（人工判定）
- 命中：08-30（火锅，1850 kcal，约为日常水平的 1.4~2 倍）
- 处理：保留在数据中，图表中标注，解读时单独说明
- 理由：真实发生的行为，删除等于美化数据；但它会造成次日体重水肿，
  影响短期趋势解读，必须可见

  **3. 半记录日 —— 整行存在，但体重未称**
- 命中：09-24（饮食与训练已记，体重 NULL）
- 性质：介于整行缺失与部分记录之间
- 处理：整行保留；热量按部分记录日规则处理，体重按缺失处理（插值仅用于均线）
- 连锁影响：可检验记录日从 48 降到 47，并参与末端均线窗口成分差异
  （机制见第四节"窗口口径坑"，交叉校验第三条即此日）

> 区分原则：**低质量记录（不可信）与真实极端值（可信但不典型）是两回事。
> 前者剔除出统计，后者标注后保留。**

## 三、填0原则

- **填0**：训练分钟、有氧距离。休息日"训练量为0"是事实（真0）。
- **留空（NaN）**：体重、热量、蛋白质、睡眠。
  0 表示"真的吃了0大卡/睡了0小时"，与"不知道"含义完全不同，
  填0会把均值拉向错误方向。

## 四、统计口径说明

- 本项目所有"日均XX"均为**记录日均值**：pandas 求均值默认跳过缺失值，
  未记录的日子既不进分子也不进分母。
- 偏差方向：漏记日多为外食/聚餐/状态混乱的日子，摄入倾向高于平时，
  因此记录日均值**可能低估真实摄入**，两个月都存在此偏差。
- 对结论的影响：体重数据几乎每日记录（仅缺3天），受影响小，
  趋势结论以体重7日均线为主；摄入的绝对水平仅供参考，
  月份间对比结论需附带口径说明。
  - 窗口口径坑：体重 NULL 落在窗口内还是窗口外，SQL"最近 7 个非空记录日"与
  Pandas"7 行内非空"给出不同末端读数（49.36 vs 49.25，差 0.11 kg）——
  两者都没错，是窗口成分定义不同，读数时必须声明口径
  （该跳NaN机制已在当前数据独立复现：末端 49.24 vs 化石 49.25）。
